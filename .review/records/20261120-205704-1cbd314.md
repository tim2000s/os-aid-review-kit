## The change, in the author's words

Extends the assistant guard from Claude Code to Codex and Gemini CLI. guard.py takes --agent; Codex refusals are a permissionDecision deny on stdout, Claude and Gemini refusals exit 2. It reads Codex's Bash and apply_patch calls (patch paths, including a patch handed to the shell) and Gemini's run_shell_command, write_file and replace. global.py on --claude --codex --gemini adds the hook to each assistant's user settings and writes the review steps (templates/assistant-instructions.md) into ~/.claude/CLAUDE.md, ~/.codex/AGENTS.md or ~/.gemini/GEMINI.md; off removes both. Settings are written through symlinks with their permissions kept, every settings file is parsed before anything changes, and off leaves files without the guard untouched. The command splitter now respects quotes, so a separator inside a quoted argument no longer splits it, while command substitutions are still checked. A live Codex session asked to commit with --no-verify was refused; Gemini CLI was not signed in on the test machine, so its guard is tested only through its documented tool names and fields. What could go wrong: Codex runs the hook only once trusted through /hooks; some specialised Codex tool paths bypass hooks; a Gemini or Codex release could rename tools or fields, which would let calls through unmatched.

## The change, in the author's words

Extends the gate from repositories where the kit is committed to every repository on the machine. kit/global.py sets git's global core.hooksPath to global-hooks/, whose dispatcher is linked under every hook name: it runs the repository's own .git/hooks entry first, then, for pre-commit, commit-msg and pre-push only, either the committed kit (exiting when the own hook is lefthook and lefthook.yml runs review.py, otherwise lefthook run, and refusing when lefthook.yml does not run the kit) or ambient mode. Ambient mode runs kit/review.py with records in ~/.review-ledger/repos/<path>/records (a git repository committed on every write), tiers copied from the matching preset on first use, the kit's TruffleHog and Semgrep configs, and lint configs from the templates where the repository has none. Opt-out is git config --local review.ambient false.

Both modes now leave out paths whose state is upstream's doing through a merge: upstream is review.upstream (local config, remote-tracking refs only) or the default branch of each remote other than origin; for each, m = merge-base(ref, tip), ignored when the base already contains m; a path is exempt only when it is the same at the base as at the fork point and the tip matches m. Checks skip symlinks.

What could go wrong: the exemption is the part that can let unreviewed code through, and three review rounds found five ways it did (own pushed branches, stale refs, reverts, a fork's own change dropped in a merge, a command-line review.upstream); each now has a test that fails when the bug is reintroduced. Turning the global hooks on changes every repository at once: pushes of work committed before the gate need retrospective records, a repository whose own hooks git ran from .git/hooks now runs them through the dispatcher, and git-lfs cannot install hooks under a global hooks path. The fix for round 3's finding was verified by tests only, not by a further review round.

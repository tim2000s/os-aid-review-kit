## The change, in the author's words

Makes the evidence the gate records true and puts it in front of the person reading a pull request.

The lint gate now fails when a linter exits cleanly and prints nothing. Every supported linter prints a SARIF document on a clean file (checked for ruff, biome, ktlint and swiftlint), so silence meant the findings were unknown and was being read as none.

invalid() is now the one rule set: record refuses on it and coverage, status and CI apply it to any record found later, so a record edited by hand is held to what its creation was (labels, important findings fixed). A test check that did not pass invalidates a record at every tier. A repository with no tests configured gets a "tests: not configured" row in every record. A high-tier record needs every other check to pass and a way back, and a change to a configured high-tier path (the dose path) needs tests that ran and passed; files that are high tier only as gate configuration do not, so a first push of a repository without tests still works.

Sign-off counts a file missing from disk, or back after a reviewed deletion, as drift; status reports only the second, since in ambient mode a missing file may belong to another branch.

pr-body now writes the pull request description: each covering record's explanation, checks, findings and way back, a forced sign-off over changed files, any file no record covers, and a collapsed table of each file's reviewed blob with a git ls-tree command that confirms it. It works in ambient mode from the ledger. The assistant instructions say to pipe it into gh pr create --body-file -.

The kit's own .review/bin copies are refreshed to match kit/.

What could go wrong: a high-tier change to the dose path in a repository whose tiers name no tests can no longer be recorded; the AndroidAPS and Trio presets ship with tests commented out, so Boost dose-path work needs a [tests] entry in its ledger tiers.toml first. All 54 ledger records and 24 installed records keep their validity under the new rules. A linter version that stops printing SARIF on clean input would now fail the gate rather than pass it.

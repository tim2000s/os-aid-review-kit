## The change, in the author's words

The lint gate ran ktlint with its default style on every repository containing Kotlin, and its --fix step formatted added Kotlin files with ktlint whatever the repository used. On Boost-autoconfig-rerun, which has no ktlint setup, this gave 703 findings, about 80 counted as new for lines written to match the surrounding code, and rewrote two added files out of the repository's style. ktlint and its formatter now run only where git shows ktlint named in an .editorconfig at any depth, a Gradle build file or a version catalogue, on either side of the change. The question is asked once, of git, for both the before and after trees, so adding or removing the setup cannot make inherited findings look new or hide new ones, and a git error fails the gate rather than skipping the linter. What could go wrong: a repository that configures ktlint some other way (a CLI wrapper script, a pre-commit config) is now not linted by ktlint, and nothing prints that ktlint was skipped, as biome and swiftlint already do not.

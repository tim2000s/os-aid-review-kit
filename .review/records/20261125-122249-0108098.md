## The change, in the author's words

The guard already refused rm, mv and editors on review records and the ledger, but git rm and git mv went through, because git was treated as a reader for those subcommands. The guard now reads the paths given to git rm and git mv, joined to any -C or --work-tree directory, and refuses the command when one of them is a record or ledger path. Ordinary git rm and git mv elsewhere are unaffected, which the new tests check. What could go wrong: a path given relative to a directory entered by a separate cd, a quoted wildcard, or --pathspec-from-file is still not seen, so this narrows the gap without closing it.

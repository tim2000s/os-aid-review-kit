## The change, in the author's words

The pre-commit secret scan failed every commit that touched AndroidAPS's google-services.json or Trio's GoogleService-Info.plist, because TruffleHog reads the AIza prefix of their Firebase keys as a Gemini API key. Those keys are public by design and already sit on the upstream repositories.

All three places that ran the scan (the ambient hook in global-hooks/dispatch, `review.py checks`, and the lefthook pre-commit that the installer writes) now call a new `review.py secrets <paths>`. It runs TruffleHog with --json. A finding still fails unless the same value is already held, in the same file, on a remote-tracking branch. Such a value is listed without failing, since it has left the machine already and the commit sends nothing new. A finding is never counted as known when TruffleHog gives a RawV2, meaning Raw is only the public half of a pair such as an AWS key ID, or when Raw is empty or spans lines. It was checked on the AndroidAPS and Trio checkouts here, where 0 new findings were reported, and by a test that fails against three mutants.

What could go wrong: every remote-tracking ref counts, private remotes and stale branches included, so a value that was pushed only to a private origin no longer blocks a later commit. CI still runs `trufflehog git --fail` and is unchanged. Repositories with the kit already installed keep their old lefthook.yml until it is regenerated.

## The change, in the author's words

span_of() measured a range from `git merge-base base tip`, which exits 1 with no output when the two share no history. After a history rewrite the pushed tip and the remote sha are unrelated, so the pre-push hook aborted with "merge-base failed" and no rewritten branch could be pushed through the gate. Now exit code 1 with no output is treated as unrelated histories and the range is measured from the empty tree, the rule for a first push, so every file the tip holds needs a record: stricter than any merge-base. Every other failure (exit 128 for a missing ref or object) still stops with the git error, so a mistyped --base cannot turn into a record of the whole tree. What could go wrong: a shallow clone that hides the common ancestor also exits 1 and is measured from the empty tree, which asks for more records, not fewer. Tests: a rewritten tip lists a file the rewrite left alone (only the empty tree lists it); a bad --base still fails and is not called unrelated; both fail on mutants of the fix.

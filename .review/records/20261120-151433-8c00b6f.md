## The change, in the author's words

Fixes the defects two rounds of fresh-context review found in the first version of the kit, and
installs the kit on its own repository.

The coverage check now accepts only records consistent with the rules, counts deletions and type
changes, treats the gate's own files (tiers, scripts, hooks, linter and scanner configuration,
workflows) as high tier, and is run per pushed ref by a lefthook script, since lefthook skipped the
pre-push command when a branch other than HEAD was pushed. Checks refuse to run when the content on
disk differs from what is being recorded, so scanners and tests read the committed content. The lint
gate fails closed when a linter is missing, crashes or prints nothing parseable, reads linter
configuration from git on each side, and keeps a deleted configuration in force for the change that
deletes it. CI checks out the pull request head rather than the merge commit, lints every non-Swift
language whatever was detected, and reads review.py and tiers.toml from the base branch.

What could go wrong: the stricter checks will block commits in repositories with untracked files when
tests are configured (the message says how to stash them), and high-tier treatment of pyproject.toml
and .editorconfig makes routine edits to them need a way back. The CI changes have not run on GitHub.

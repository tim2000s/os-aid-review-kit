## The change, in the author's words

Adds a way to turn the review gate on for one repository by asking an assistant, so that a person with little coding experience can add it to their process with one sentence.

kit/enable.py sets the repository's own core.hooksPath to the kit's dispatcher and review.ambient true, commits nothing, adds the guard and the review steps for each assistant found in the user's settings, and prints a brief for the assistant: the tier preset, whether tests are configured, which tools are missing and the command to install them, and the steps for every change ending with pr-body piped into gh pr create. enable.py --status says whether the gate runs here. kit/disable.py undoes it and the guard refuses running it, as it refuses global.py off. The assistant instructions now apply only where the gate is on, and say how to check.

The guard itself refuses everywhere, as before. A version that relaxed it outside gated repositories was reviewed for three rounds; each found a new way for a command to reach a gated repository unseen (opted-out and husky repositories, a cd to /tmp, subshells, chdir, env --chdir, git bisect run), so it was dropped. The guard gains two fixes: the git subcommand is found past -C, -c, --git-dir and --work-tree, and running disable.py is refused unless the command only reads or stages it.

Also fixes a crash reported from another session: review.py record failed on a finding without a summary and left an empty record file, because write() opened the file before rendering. invalid() now requires a summary and write() renders first. The reordering is defence and has no test of its own, since invalid() now refuses such a record before write() is reached.

What could go wrong: an assistant in an unrelated repository is still refused --no-verify; the person can run it. enable.py edits the assistant's user settings and appends the review-steps block to its instructions file, which a person may not want; disable.py leaves those in place. The guard and hooks still run from the kit checkout's working tree, which the next change addresses.

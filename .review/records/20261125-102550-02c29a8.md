## The change, in the author's words

The hooks and the assistant guard now run from ~/.review-kit, a copy of the kit checkout's last commit, never from the checkout. Before this, every repository on the machine ran the checkout's working tree, so an uncommitted edit changed the live gate at once; on 25 November 2026 a half-applied edit to guard.py refused every file edit until it was repaired.

global.py on and enable.py make the copy where none exists, taking HEAD as it stands (for a new user, the clone just made), point the hooks path and the guard command there, and repoint any older guard entries in the assistants' settings without adding instruction blocks. global.py update, which the guard refuses from an assistant and which runs only from the live copy, replaces the copy with the checkout's HEAD when HEAD descends from the live commit and every file changed since then has a valid review record, judged by the live commit's own review.py and tier settings. A copy without its DEPLOYED record is not replaced by on or enable.py. The guard command ends in `|| exit 2`, so a missing copy refuses assistant calls rather than allowing them. The guard protects the copy (and the ledger, whose bare directory was unprotected) from shell writes, now including rsync, ditto, tar and unzip extraction, touch, mkdir, rmdir, trash, gio, find -delete/-exec and perl -i; it lets an assistant run global.py only as on or status. The assistant instructions point at the copy.

What could go wrong: the guard's list of writing commands is a deny-list and cannot be complete (osascript, a Python one-liner and any script written to disk are not inspected), so an assistant set on deleting the copy can still do it, after which the next on or enable.py copies HEAD unchecked; the README says so. Git runs no hooks from a hooks path that does not exist, so a deleted copy also stops the commit gate until a person runs on; global.py status shows it. A repository set up with enable.py before this change keeps the checkout's hooks path until enable.py is run in it again. The person's CLAUDE.md still names ~/os-aid-review-kit/kit/review.py, which works but runs the checkout's copy.
